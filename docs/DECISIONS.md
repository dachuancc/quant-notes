# 约定与决策（ADR-lite）— quant-notes

> 每个关键约定一条，编号递增，**只增不改**。要推翻旧约定，新增一条并注明「取代 D<n>」。

---

## D1 目录按"研究环节"分类，而非按难度

- **决定**：`math / statistics / markets / strategies / backtesting / derivatives`。
- **考虑过的其他选项**：
  - *按难度分类*（入门 / 进阶 / 高级）—— 检索笔记时人想的是"我在做哪一步"
    （建因子？做回测？），而不是"这有多难"。
  → 选按研究环节分类，让每篇笔记落到工作流里的确定位置。
- **影响**：新增笔记前先确认它属于哪个环节；跨环节的内容拆成多篇互相链接。

## D2 README 是唯一索引，且由 CI 强制

- **决定**：`README.md` 必须是所有笔记的入口；`scripts/check_links.py` 校验
  ①链接指向的文件存在、②没有"孤儿笔记"（存在于 `notes/` 但未被索引）。
- **考虑过的其他选项**：
  - *靠自觉维护索引* —— 笔记仓库最典型的退化就是"文件越堆越多、README 长期失修"。
  → 选把索引一致性做成**会失败的测试**，比靠自觉可靠。
- **影响**：新增笔记 = 加文件 + 改 README，二者缺一 CI 就红。见 `tests/test_links.py`。

## D3 许可证用 CC BY 4.0

- **决定**：文字内容采用 CC BY 4.0（而非 MIT）。
- **考虑过的其他选项**：
  - *MIT* —— 是为代码设计的许可证，用在文字作品上不合适。
  → 选 CC BY 4.0：允许转载/改编但要求署名，符合"分享但保留出处"的意图。
- **影响**：`LICENSE` 为 CC BY 4.0 全文；转载需注明出处。

## D4 宁可留 TODO，不写填充内容

- **决定**：没有自己思考的通用知识不写；目录里用 `> 待写：…` 占位。
- **考虑过的其他选项**：
  - *用 AI 批量生成通用内容把仓库填满* —— AI 时代最不缺的就是"看起来很全"的通用内容；
    那些内容对读者和自己都没有增量。
  → 选宁可留 TODO：个人笔记的价值在于**视角与踩坑经验**。
- **影响**：仓库可能长期"不全"，但每篇都有信息量。这条是本仓库的**核心红线**。

## D5 每篇笔记固定六段结构

- **决定**：一句话结论 → 定义/公式 → 性质与直觉 → **陷阱** → 关联实现 → 参考。
- **考虑过的其他选项**：
  - *自由结构*（每篇随内容长短）—— 阅读成本高，且"陷阱"一节最容易在自由结构下被省略。
  → 选固定六段结构：降低阅读成本，并把"陷阱"变成强制项。
- **影响**：评审新笔记时，缺"陷阱"或"关联实现"视为不合格。
