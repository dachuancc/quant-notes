# 未来函数（Look-ahead Bias）

> **一句话**：策略在 $t$ 时刻用了 $t$ 之后才可知的信息，回测结果系统性虚高。
> 这是回测里最常见、也最隐蔽的一类错误。

## 最隐蔽的一种：信号与收益同时生效

**错误**——当天信号当天就吃到当天收益：

```
position_t = signal_t           # 若 signal_t 依赖 P_t（当日收盘价）
pnl_t      = position_t * r_t   # 就等于用当天收盘信息赚当天收益
```

**正确**——T 日收盘得到的信号，T+1 日才持有：

$$position_t = signal_{t-1}$$

即回测框架里的一句 `positions = signal.shift(1)`。

**最小反例**：价格从 100 跳到 200，信号在暴涨当天才变成 1。
- 若当天生效：白赚 100%（虚假）；
- T+1 生效：持仓从次日开始，而价格已不动，收益为 0（真实）。

## 常见形式清单

| 形式 | 后果 |
|---|---|
| 用**全样本**参数（z-score 的均值/方差、回归系数、标准化因子） | 参数偷看了未来 |
| 财报用"最终修正值"而非 point-in-time 数据 | 高估基本面策略 |
| 指数成分股用"今天的名单"回测历史 | 幸存者偏差 |
| 复权价用**最新**复权因子回填历史 | 前视 |
| 假设收盘信号能在**当天收盘**成交 | 时间穿越 |
| 数据清洗时剔除了后来才退市的股票 | 幸存者偏差 |
| 特征用了结算日之后才公布的宏观数据 | 发布时滞被忽略 |

## 如何防

1. **框架层强制 T+1**（`shift(1)`）——最可靠，改一处、全局受益。
2. 参数只用**滚动窗口**（`rolling` / `expanding`），绝不用全样本统计量。
3. 使用 **point-in-time** 数据；财报按**公告日**而非报告期对齐。
4. 样本内 / 样本外切分 + **walk-forward** 验证。
5. **单元测试**：构造"当日暴涨才触发买入"的场景，断言净值不受影响。

## 关联实现

- `backtest-lab` / `engine.py`：`positions = signal.shift(1)`。
- 守护测试：`test_no_lookahead_positions_lag_signal_by_one`、
  `test_signal_cannot_earn_same_day_return`——它们把这条不变量钉死，防止被"优化"掉。
